# Lib Quest 운영자 가이드

**대상: 사서 / 콘텐츠 운영자** (개발자용 문서가 아니다. 코드/서버 관련 내용은 [DEVELOPMENT.md](DEVELOPMENT.md) 참고)

## 왜 이 화면을 보는가

Lib Quest는 실제 장서 데이터를 사람이 검수하고 공개해야만 이용자에게 노출되는 구조다.

```
Data4Library 후보 → Quest 후보 구성 → Mission/Editorial 콘텐츠 작성 → 운영자 검수 → 이용자 공개 → 이용자 행동
```

- **데이터가 결정하는 것**: 어떤 책이 실제로 서가에 있는지, ISBN·청구기호·서가 위치가 무엇인지 — Data4Library `itemSrch` 원본 그대로.
- **사람이 결정하는 것**: Mission 문구와 teaser/hook/question이 그 Step/책에 실제로 맞는 내용인지, 검수를 마쳤는지, 이용자에게 지금 공개해도 되는지.

## 1. Admin 진입

**https://quest.lib.lc/admin/review**

메인 화면(`https://quest.lib.lc`)의 `운영자 검수` 버튼으로도 들어갈 수 있다. 화면 상단에 `DEMO ADMIN` 배지가 붙어 있다 — 이번 공모전 MVP에는 로그인/권한 시스템이 없다는 뜻이다(아래 "현재 MVP 제약" 참고). URL을 아는 사람은 누구나 이 화면에서 콘텐츠를 수정할 수 있다.

## 2. 도서관 선택

상단 탭에서 도서관을 고른다(현재 4곳). 탭을 클릭하면 `/admin/review?library=libCode`로 이동해 해당 도서관 데이터만 보여준다. 기본은 대표 시연 도서관(원신흥도서관)이다.

그 아래 요약 카드에서 이 도서관의 퀘스트/단계/후보 도서/실제 도서 수와, Mission·Editorial 검수 완료 수, 공개된 콘텐츠 수를 한눈에 볼 수 있다. 전부 실시간 DB 집계이며 가짜 수치가 아니다.

## 3. Quest 선택

퀘스트 카드에 제목·설명·게시 상태(이용자 공개 중/미게시)가 보인다. 그 아래 Step 목록에서 원하는 Step을 클릭하면 아코디언이 펼쳐진다. **Quest를 새로 만들거나 삭제하는 기능은 없다** — Quest 구성 자체는 `data/libraries/<libCode>/quest-curation.json`이 원본이다.

## 4. Mission 수정

Step을 펼치면 맨 위에 **Mission Content** 편집기가 있다.

- `missionTitle`: Step 진입 시 보여줄 짧은 제목(예: "첫 번째 흔적")
- `missionNarrative`: 그 아래 탐험 서사 한두 문장

텍스트를 고친 뒤 아래 버튼 중 하나를 누른다. 텍스트는 어떤 버튼을 눌러도 함께 저장되므로, 입력만 하고 버튼을 아무거나 눌러도 내용이 사라지지 않는다.

## 5. Book Editorial 수정

Step 안의 후보 도서 4권이 아래에 나열된다. ISBN/저자/청구기호/서가 위치 등은 **읽기 전용**이다(아래 "수정할 수 없는 값" 참고). 각 행의 `콘텐츠 편집`을 누르면 그 책의 Editorial 편집기가 펼쳐진다.

- `hook`: "이 책이 끌리는 이유" — 발견 직후 가장 먼저 보여주는 한 줄
- `teaser`: "이런 책이에요" — 짧은 소개
- `question`: "책을 펼치기 전에" — 읽기 전 질문

콘텐츠가 아직 없는 책은 세 칸이 비어 있고 `(아직 DB에 콘텐츠 없음)`이 표시된다 — 입력 후 저장하면 그 자리에서 새로 만들어진다.

## 6. 저장

`저장` 버튼은 검수/공개 상태를 바꾸지 않고 본문만 저장한다. 단, **이미 `검수 완료` 상태였던 콘텐츠의 본문을 고쳐서 저장하면 자동으로 `검수 필요` + `비공개`로 되돌아간다** — 한 번 검수를 마친 문구를 몰래 바꿔서 계속 공개 상태로 두지 않기 위함이다(재검수 필요).

## 7. 검수 완료

문구를 확인했다면 `검수 필요`(아직 확정 아님을 표시) 또는 `검수 완료`를 누른다. `검수 완료`를 눌러야만 다음 단계인 "공개"가 가능해진다.

## 8. 공개

`검수 완료` 상태에서만 `공개` 버튼이 실제로 콘텐츠를 이용자에게 노출한다. 아직 검수 완료가 아닌 상태에서 공개를 시도하면 "검수 완료 후 공개할 수 있어요."라는 안내와 함께 거부된다. 공개된 콘텐츠는 `공개` 배지로 표시되며, 언제든 `비공개로 전환`을 눌러 다시 숨길 수 있다(검수 상태는 `검수 완료`로 유지된다 — 재검수 없이 다시 공개 가능).

## 9. 사용자 반영 확인

공개한 직후 이용자 Quest 화면(`/quests/...`)에서 해당 ISBN을 인증하면 방금 저장한 hook/teaser/question이 BookInfo 화면에 그대로 나타난다. Mission도 마찬가지로, Step 진입 화면에 방금 공개한 missionTitle/missionNarrative가 보인다. 별도 캐시 무효화 없이 다음 요청부터 바로 반영된다(요청마다 DB를 조회하기 때문).

## 10. 데모 데이터 초기화

화면 우상단의 `데모 데이터 초기화` 버튼은 **현재 선택된 도서관의** Mission/Editorial 콘텐츠만 초기 baseline(발표용으로 미리 작성해 둔 원본)으로 되돌린다. 확인 모달에서 한 번 더 확인해야 실행된다.

- **되돌아가는 것**: hook/teaser/question, missionTitle/missionNarrative, 검수 상태, 공개 여부
- **절대 바뀌지 않는 것**: 장서(Book), Quest/Step 구성, 후보 도서 관계

발표 리허설 중 이것저것 수정해 보다가 원래 시연 콘텐츠로 빠르게 되돌리고 싶을 때 사용한다.

**주의**: 이 초기화는 Header의 `처음부터` 버튼과 완전히 다른 기능이다. `처음부터`는 브라우저에 저장된 **이용자의** 진행 상태(Quest 세션·발견 도감·관심·오늘의 한 권)를 지우는 것이고, `데모 데이터 초기화`는 **운영 콘텐츠 DB**를 되돌리는 것이다. 서로 영향을 주지 않는다.

## 수정할 수 없는 값

다음은 이 화면에서도(운영자 화면이어도) 읽기 전용이다 — Data4Library 실장서 데이터와 큐레이션 원본이기 때문이다.

- ISBN, 책 제목, 저자, 청구기호, 분류(className), 자료실/서가 위치, 데이터 출처
- 어떤 도서관에 속하는지(library), Step의 후보 관계(QuestCandidate), Step 순서
- Quest 자체의 생성/삭제

이 값이 실제 서가 상황과 다르면(책이 옮겨졌거나 폐기된 경우 등) 개발팀에 알려 해당 도서관의 큐레이션 데이터(`data/libraries/<libCode>/quest-curation.json`)를 다시 검토해야 한다.

## ISBN 복사

발표·데모 환경에서는 실제 도서관에 가지 않고도 후보 도서의 ISBN을 그대로 복사해 사용자 화면의 "ISBN 직접 입력"에 붙여넣어 테스트할 수 있다. 후보 행의 ISBN 옆 `복사` 버튼을 누르면 클립보드에 복사된다.

## 데이터 출처

**https://quest.lib.lc/data-source**

어떤 API로, 언제, 몇 건을 수집했는지는 이 화면에서 확인한다.

## 현재 MVP 제약

- **로그인/권한 시스템이 없다.** URL을 아는 사람은 누구나 이 화면에서 콘텐츠를 수정할 수 있다 — 그래서 화면 상단에 `DEMO ADMIN`을 명확히 표시한다. 실제 상용 운영에는 사서 인증, 역할 기반 권한(RBAC)이 반드시 필요하다.
- **수정 이력(audit log)이 없다.** 누가 언제 수정했는지는 기록하지 않는다(인증이 없어 "누가"를 의미 있게 기록할 수 없다). 각 콘텐츠의 최종 수정 시각(`updatedAt`)만 서버에 남는다.
- **수정 가능 범위가 운영 콘텐츠로 제한된다.** Book/Quest/QuestStep/QuestCandidate(장서·Quest 구성)는 이 화면에서 절대 수정/삭제할 수 없다 — 오직 Mission Content와 Book Editorial만 편집 가능하다.
- **실시간 대출 가능 여부를 보여주지 않는다.** 표시되는 장서 정보는 특정 시점에 수집된 등록 정보다.
- **대전 지역 도서관 4곳(원신흥·갈마·가수원·노은)만 지원한다.**
- **자동 승인/일괄 편집 같은 CMS 기능은 없다.** 저장·검수 필요·검수 완료·공개·비공개 5개 동작만 지원하는 최소 워크플로다.
